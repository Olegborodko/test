# Астрологический сайт (в разработке)

Веб-приложение по астрологии: пользователь вводит данные рождения и получает разбор
натальной карты и предсказания. Пишется с нуля в этом репозитории.
Правила разработки и конвенции кода — в `AGENTS.md`.

## Статус

Этап 2: работает серверный расчёт карты (западная + ведическая) и форма ввода.
На хостинге опубликован preview. Пользователей, вход через Google и текстовые трактовки пока нет.

## Что известно

- Сайт делается с нуля, без готовых шаблонов.
- Технологии: чистые HTML + CSS + JS, без сборки и зависимостей (пока хватает).
- Владелец проверяет результат с телефона (Android), поэтому приоритет — мобильный вид.
- Исходники хранятся в GitHub-репозитории `Olegborodko/test`.
- В перспективе: вход пользователей через Google, хранение данных рождения, генерация
  разбора карты на сервере (ключ API не попадает в браузер).

## Требования к продукту

- Сайт — для обычных людей: объясняет, что такое астрология, что такое натальная карта,
  как её читать. Не «сервис предсказаний», а понятный и содержательный разбор.
- Нужны **обе традиции**: западная (тропический зодиак) и ведическая (сидерический зодиак).
- **Приоритет — точность и достоверность расчёта**, а не скорость и не количество запросов.
  Лимиты не важны: даже 10 карт в день достаточно.

## Хостинг

Хостинг — **Sites** (Cloudflare Workers), бесплатно, деплой из чата агента.

- Preview: <https://site-6e778d474b48492e9ec165bf385d660e.freebuff.page>
- Production: ещё не публиковался.

Сборка для деплоя — `./scripts/build.sh`: складывает статику в `dist/public/`, бандлит Worker
(вместе с WASM-движком) и пишет `dist/manifest.json`. `dist/` в git не попадает.

## Структура

```
index.html             главная страница с формой
assets/css/style.css   стили
assets/js/main.js      форма и вывод карты
worker/index.js        роутер: /api/chart и отдача статики

```

## Как запустить локально

```bash
npm install
npm run dev
```

Поднимает Worker на `0.0.0.0:3000`: страница и API на одном адресе, как на хостинге.
Страница одна — открывать `index.html` файлом нельзя, ей нужен `/api/chart`.
После правок статики перезапустить `npm run dev` (он пересобирает `dist/`).

## API

`POST /api/chart`

```json
{ "date": "1990-06-15", "time": "18:30", "city": "Москва" }
```

Вместо `city` можно передать `latitude`, `longitude` и `timeZone` (IANA, например `Europe/Moscow`).
`time` — местное время рождения; перевод в UTC учитывает исторические часовые пояса и летнее время.

Ответ: `utc`, `julianDay`, `western` (тропический зодиак, дома Плацидуса: планеты, ASC, MC, куспиды)
и `vedic` (сидерический зодиак, аянамша Лахири: раши, накшатра с падой, дома от ASC по целым знакам).
Плюс блок `reading` — готовый текст разбора: «Кто ты», «Что ты чувствуешь», «Как тебя видят»
и короткие строки по остальным планетам. Тексты лежат в `worker/interpretation.js`.
Коды ошибок: `400` — некорректные данные, `502` — город не найден или геокодер недоступен.

## Варианты расчёта карты

1. **Swiss Ephemeris в Cloudflare Worker (WASM)** — целевой. Эталонная точность,
   оба зодиака и все системы домов в одной библиотеке. Лицензия AGPL (или коммерческая,
   CHF 700) — значит, проект остаётся открытым. Была неизвестна работоспособность
   в Worker: **проверено, работает** (см. ниже).
2. **Worker + astronomy-engine** (JS, MIT) — если WASM не пойдёт. Точность ±1′,
   домов и аспектов нет — писать самим.
3. **Отдельный сервер** (Node/Python + pyswisseph или Kerykeion) — работает без трюков,
   но бесплатного нормального хостинга нет: от ~5$ в месяц. Крайний случай, если нужен
   закрытый код без AGPL.

## Проверка варианта 1 (Swiss Ephemeris в Worker)

Дата теста: 2026-10-25. Пакет `@kuntay/swisseph` 0.2.2 — Swiss Ephemeris 2.10.03,
собран в WebAssembly (563 КБ, без файлов эфемерид, режим Moshier).

Запущено в **workerd** (`wrangler dev`) и сверено с эталоном (pyswisseph 2.10.03):

| Что | WASM в Worker | pyswisseph |
|---|---|---|
| Sun | 84.2290562 | 84.2290562 |
| Moon | 346.7517324 | 346.7517324 |
| Asc (Placidus) | 225.4550347 | 225.4550347 |
| Sun, сидерика Lahiri | 60.5017563 | 60.5017563 |
| Asc, сидерика Lahiri | 201.7277348 | 201.7277348 |

Совпадение до 7-го знака по всем 10 планетам, домам и обоим зодиакам.
Скорость: 6 мс на старт движка, 8 мс на полный расчёт.

Что понадобилось починить (особенности загрузчика пакета, не самого движка):

- Worker не может компилировать wasm из байтов в рантайме → бинарь подключается как
  готовый модуль, а `WebAssembly.instantiate` подменяется на его использование;
- в workerd пустой `import.meta.url` → заглушка для `new URL(..., import.meta.url)`;
- загрузчик принимает Worker за Node → `process` убирается перед импортом.

Вывод: вариант 1 годится. Дальше — расчёт карты на сервере (ключ API и логика не в браузере)
и сравнение с полными файлами эфемерид, если понадобится точность выше Moshier.

## Карта развития (что ещё есть в астрологии)

Натальная карта — только фундамент. Ниже — что есть дальше и что из этого стоит делать сайту.

**Ближайшее (закрывает почти весь спрос):**

- **Трактовки натальной карты** — человеческим языком: Солнце, Луна, асцендент, планеты во знаках и домах.
- **Транзиты** — текущее небо относительно карты. Это и есть прогнозы на день/месяц/год.
- **Совместимость (синастрия)** — наложение двух карт: насколько люди подходят друг другу.
- **Соляр** — карта на момент возвращения Солнца: прогноз на год вперёд.
- **Даши** (в ведической) — периоды жизни по звёздам.

**Глубже (для интересующихся):**

- Прогрессии и дирекции — карта, сдвинутая во времени; этапы жизни.
- Управители домов, достоинства планет, жребии (парсы), секта — техника чтения карты.
- Аспекты и орбисы — углы между планетами; в базовой версии нет.
- Мидпойнты, гармоники, фиксированные звёзды, астероиды.
- Ведическая ветка: дробные карты (навамша и др.), йоги, аштакаварга, гочара.

**Не для этого сайта:**

- Хорарная (ответ на вопрос по карте момента), элективная (выбор даты), мунданная (карты стран)
  — узкие профессиональные техники, для обычного пользователя непонятны.

## Открытые вопросы

Пока не решено — нужно от владельца:

1. **Вход через Google** — нужен проект в Google Cloud Console (client ID и secret).
   Пока не создан; без него вход не сделать.
2. **Как запустить Swiss Ephemeris в Worker** — нужна сборка в WebAssembly. Это главный
   технический риск этапа; если не заведётся за разумное время, временно используем
   astronomy-engine.
3. **Какой текст выдаётся пользователю** — шаблонный разбор по правилам или генерация языковой моделью.
   Второе требует API-ключа и оплаты за запросы.
4. **Набор экранов.** Предложение по умолчанию: форма ввода данных рождения → карта → текстовый разбор.
5. **Визуальный стиль.** Референсы, цвета, логотип — или на мой вкус.
6. **Домен.** Нужен ли свой; сейчас бесплатный поддомен хостинга.

## Журнал решений

- **Стек — чистая статика.** Не тянем фреймворк и сборку, пока задача не потребует.
  Причина: сайт небольшой, мгновенный предпросмотр с телефона, нет зависимостей и сборки.
- **Mobile-first.** Базовый CSS — под узкий экран, расширения через `min-width`.
- **Хостинг — Sites (Cloudflare Workers).** Бесплатно, деплой без сторонних аккаунтов и карт,
  позже там же доступны база данных и секреты для ключей. Отдельная сборка в `dist/` — только
  для деплоя, источник правды остаётся в корне.
- **Расчёт — Swiss Ephemeris (Astrodienst).** Эталон точности: тропический и сидерический
  зодиак, дома, аспекты — всё в одной библиотеке. Лицензия AGPL или коммерческая (CHF 700).
  Берём AGPL: это значит, что проект должен оставаться открытым. Готовые astrology API не берём:
  у всех либо лимиты, либо непонятное качество, а нам нужна максимальная точность.
- **Расчёт — на сервере, а не в браузере.** Движок и логика живут в Worker: клиент не тянет
  мегабайты WASM, а позже там же будет ключ языковой модели.
- **Геокодирование — Open-Meteo.** Бесплатно, без ключа и регистрации: город → координаты и часовой пояс.
- **Контент и стиль** — после ответов на вопросы выше.
