# Астрологический сайт (в разработке)

Веб-приложение по астрологии: пользователь вводит данные рождения и получает разбор
натальной карты и предсказания. Пишется с нуля в этом репозитории.
Правила разработки и конвенции кода — в `AGENTS.md`.

## Статус

Этап 1: на хостинге опубликована страница-заглушка «Привет». Приложение ещё не начато.

## Что известно

- Сайт делается с нуля, без готовых шаблонов.
- Технологии: чистые HTML + CSS + JS, без сборки и зависимостей (пока хватает).
- Владелец проверяет результат с телефона (Android), поэтому приоритет — мобильный вид.
- Исходники хранятся в GitHub-репозитории `Olegborodko/test`.
- В перспективе: вход пользователей через Google, хранение данных рождения, генерация
  разбора карты на сервере (ключ API не попадает в браузер).

## Требования к продукту

- Сайт — для обычных людей: объясняет, что такое астрология, что такое натальная карта,
  как её читать. Не «сервис предсказаний», а понятный и содержательный разбор.
- Нужны **обе традиции**: западная (тропический зодиак) и ведическая (сидерический зодиак).
- **Приоритет — точность и достоверность расчёта**, а не скорость и не количество запросов.
  Лимиты не важны: даже 10 карт в день достаточно.

## Хостинг

Хостинг — **Sites** (Cloudflare Workers), бесплатно, деплой из чата агента.

- Preview: <https://site-6e778d474b48492e9ec165bf385d660e.freebuff.page>
- Production: ещё не публиковался.

Сборка для деплоя — `./scripts/build.sh` (раскладывает `index.html` и `assets/` в `dist/`,
`dist/` в git не попадает). Локальный предпросмотр — `python3 -m http.server 3000`.

## Структура

```
index.html             главная страница
assets/css/style.css   стили
assets/js/main.js      скрипты
assets/img/            картинки и иконки
worker/index.js        Worker, отдающий статику на хостинге
scripts/build.sh       подготовка dist/ к деплою
AGENTS.md              правила для ИИ-агентов
```

## Как запустить локально

Открыть `index.html` в браузере — этого достаточно. Или поднять статический сервер:

```bash
python3 -m http.server 3000
```

## Открытые вопросы

Пока не решено — нужно от владельца:

1. **Вход через Google** — нужен проект в Google Cloud Console (client ID и secret).
   Пока не создан; без него вход не сделать.
2. **Как запустить Swiss Ephemeris в Worker** — нужна сборка в WebAssembly. Это главный
   технический риск этапа; если не заведётся за разумное время, временно используем
   astronomy-engine.
3. **Какой текст выдаётся пользователю** — шаблонный разбор по правилам или генерация языковой моделью.
   Второе требует API-ключа и оплаты за запросы.
4. **Набор экранов.** Предложение по умолчанию: форма ввода данных рождения → карта → текстовый разбор.
5. **Визуальный стиль.** Референсы, цвета, логотип — или на мой вкус.
6. **Домен.** Нужен ли свой; сейчас бесплатный поддомен хостинга.

## Журнал решений

- **Стек — чистая статика.** Не тянем фреймворк и сборку, пока задача не потребует.
  Причина: сайт небольшой, мгновенный предпросмотр с телефона, нет зависимостей и сборки.
- **Mobile-first.** Базовый CSS — под узкий экран, расширения через `min-width`.
- **Хостинг — Sites (Cloudflare Workers).** Бесплатно, деплой без сторонних аккаунтов и карт,
  позже там же доступны база данных и секреты для ключей. Отдельная сборка в `dist/` — только
  для деплоя, источник правды остаётся в корне.
- **Расчёт — Swiss Ephemeris (Astrodienst).** Эталон точности: тропический и сидерический
  зодиак, дома, аспекты — всё в одной библиотеке. Лицензия AGPL или коммерческая (CHF 700).
  Берём AGPL: это значит, что проект должен оставаться открытым. Готовые astrology API не берём:
  у всех либо лимиты, либо непонятное качество, а нам нужна максимальная точность.
- **Контент и стиль** — после ответов на вопросы выше.
