# Правила для ИИ-агентов

Этот файл — инструкция для любого ИИ-агента (и для человека), который работает с проектом.
Читай его перед изменениями и следуй ему; если правило мешает задаче — сначала спроси владельца.

## Что это за проект

Статический сайт, который пишется с нуля. Что именно за сайт, для кого и из каких страниц —
см. `README.md`. Там же статус и принятые решения.

## Стек

- **Чистая статика**: HTML + CSS + JavaScript, без фреймворка.
- **Никакого шага сборки** и никаких зависимостей, пока они реально не нужны.
  Не добавляй `package.json`, бандлер, TypeScript, Tailwind и библиотеки «на будущее».
- Если задачу нельзя решить без тулинга (нужна сборка, роутинг, шаблоны) — предложи это
  владельцу как отдельное решение и объясни, зачем. Только после согласия добавляй.
- Целевая среда — современные браузеры, прежде всего **мобильные** (сайт проверяется с телефона).

## Структура

```
index.html          главная страница
assets/css/style.css
assets/js/main.js
assets/img/         изображения, иконки
README.md           описание проекта, статус, решения
AGENTS.md           этот файл
```

Новые страницы — отдельными `.html` в корне. Общие стили — только в `assets/css/style.css`,
общий JS — только в `assets/js/main.js`. Не дублируй стили внутри страниц и не пиши инлайновые
`style="..."`, кроме действительно одноразовых случаев.

## Конвенции кода

- HTML: семантичные теги (`header`, `nav`, `main`, `section`, `footer`), `lang="ru"`,
  все изображения с `alt`, формы с `label`.
- CSS: имена классов в `kebab-case`, CSS-переменные для цветов и отступов в `:root`,
  мобильный вид — базовый, расширения через `min-width` (mobile-first).
- JS: `const`/`let`, обычные функции и модули, без глобальных переменных, без jQuery.
- Текст на сайте — по-русски. Имена переменных, классов, файлов и комментарии в коде — по-английски.
- Форматирование: 2 пробела, одинарные кавычки в JS, точка с запятой.

## Как отвечать владельцу

Владелец читает ответы с телефона и не хочет много текста.

- Коротко и ясно. Сначала результат, потом — при необходимости — детали.
- Не пересказывать задачу, не объяснять очевидное, не расписывать варианты, если выбор уже сделан.
- Списком вместо абзацев, когда элементов больше двух.
- Максимум — несколько сотен слов. Всё, что длиннее, — только если владелец прямо просит разбор.

## Правила работы

1. Делай минимальное изменение, которое решает задачу. Не рефактори то, о чём не просили.
2. Правь существующие файлы вместо создания новых. Новый файл — только если он нужен по структуре выше.
3. Не удаляй и не переписывай чужие правки без явной просьбы.
4. **Секреты в репозиторий не попадают.** Ключи, токены, пароли — только в переменные окружения
   или секреты хостинга, никогда в файлы проекта и никогда в чат.
5. Ничего не публикуй в интернет (деплой, пуш в основную ветку) без явного разрешения владельца.
6. Не трогай `.git`, не переписывай историю.

## Как проверить результат

Сайт проверяется в браузере телефона через локальный dev-сервер в облачной машине:

```bash
python3 -m http.server 3000 --bind 0.0.0.0
```

Сервер запускать в фоне с логом в файл, слушать `0.0.0.0:3000`, затем проверить HTTP-ответ
и отдать владельцу preview.

Перед тем как считать задачу сделанной:

- страница отдаётся по HTTP со статусом 200 и без ошибок в консоли браузера;
- вёрстка не разъезжается на узком экране (проверять на ширине ~375px);
- нет битых ссылок и отсутствующих файлов;
- проверены и десктопный, и мобильный вид.

Если проверка не удалась — так и напиши, что именно не проверено.

## Git

- Ветка для работы — та, что выдана чату (`freebuff/...`), не `main`.
- Коммит — одна логическая правка, сообщение по-английски в императиве:
  `Add hero section`, `Fix mobile nav overlap`.
- Пуш и мерж — только по просьбе владельца.
